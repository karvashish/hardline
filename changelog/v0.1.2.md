# v0.1.2 — 2026-05-29

Release-pipeline automation and documentation. No runtime behavior changes for end users running existing profiles.

### Release Engineering

- New `validate-release-pr.yml` workflow enforces release-PR shape: title pattern `[release] version X.Y.Z` (with optional `-prerelease` suffix), exactly one commit, only `internals/cli/version.json` / `CHANGELOG.md` / `changelog/*.md` modified, embedded version field matches the title, target tag `v<version>` does not already exist, and required files (`internals/cli/version.json`, `CHANGELOG.md`, `changelog/v<version>.md`) are all present in the diff.
- Validator also blocks non-release PRs from touching `internals/cli/version.json`, preventing silent drift between the embedded version and released tags.
- New `tag-release.yml` workflow runs on push to `main`, detects squashed release commits, creates and pushes the annotated `v<version>` tag, then dispatches `release.yml` via `workflow_dispatch` — sidesteps GitHub's `GITHUB_TOKEN` anti-recursion rule which would otherwise suppress the tag-triggered release build.
- Required status checks on `main` extended to include `Validate release PR shape` and `Analyze (Go)`.

### Documentation

- New [`docs/releasing.md`](../docs/releasing.md) describing the end-to-end release flow, what CI enforces, and why the embedded `version.json` is the source of truth instead of build-time `git describe`.
- README links to the new release doc from the Internals section.
