# v0.2.0 — 2026-08-06

Plugin-owned rollback and conflict detection, a new `file_meta` plugin, hardened trust boundaries, macOS builds, and a published documentation site. **This release breaks the external plugin contract** - plugins built against 0.1.x fail to load until they implement `Rollback` and `DetectConflict`.

Supersedes the `0.2.0-rc1` and `0.2.0-rc2` prereleases; everything below is the full set of changes since v0.1.2.

### Breaking Changes

- `pluginapi.Plugin` now requires `Rollback` and `DetectConflict` alongside `Apply`, `Plan`, and `Capture`. The registry rejects any plugin leaving either nil (`plugin "<name>" is missing Rollback func`), and one rejected plugin aborts loading for the whole plugin directory. Rollback and conflict detection are no longer centralised in `internals/rollback`; they dispatch through the registry to the owning plugin. See [`docs/profiles/external-plugins.md`](../docs/profiles/external-plugins.md) for the migration and [`pluginprojects/firewalltemplate/handlers.go`](../pluginprojects/firewalltemplate/handlers.go) for a worked example.

### Security

- Profile-supplied strings no longer reach a root shell unquoted. `strconv.Quote` produces Go double-quoted strings, and command substitution expands inside double quotes in POSIX `sh`, so `$(...)` or a backtick in a service unit name, managed destination, or `file_meta` target executed as root under `sudo -n sh -lc`. Every command-building call site now quotes with `pluginapi.ShellArg`; the root write path in `internals/remote` quotes all three of its operands, where it previously quoted none.
- Root-executed inputs are whitelisted rather than merely quoted, which also closes argument injection (a unit named `--force`) and does not depend on every future call site remembering the helper. Service units, managed and `file_meta` paths, owner and group names, and package names and versions are each bounded to a minimal safe character set, and `genschema` emits the same patterns as per-plugin config constraints so a hostile profile fails at `verify`, before hardline connects to any host.
- A signed profile can no longer reference content its signature does not cover. The `actions` and `templates` arrays were unconstrained and resolved with a bare `filepath.Join`, so a profile could declare `../shared/x.json` and have hardline read unsigned, externally mutable content. Entries are now pattern-bound, resolved through a check that rejects absolute paths, `..` segments and symlinked-subdirectory escapes, and `verify` asserts that every declared action and template appears in the signed manifest.
- Verify, plan and apply no longer each re-read the profile from disk. `verify` returns an immutable verified bundle that plan, apply and rollback consume, and apply recomputes the manifest digest immediately before its first write, so anything editing the profile directory after the integrity check aborts the run instead of silently changing what gets applied.
- CodeQL scans both Go and Actions workflows with the `security-extended` query suite.

### Plugins

- New `file_meta` plugin applies `chmod`/`chown`/`chattr` to existing paths, with full capture, rollback, and conflict detection. Documented in [`docs/profiles/file-meta-plugin.md`](../docs/profiles/file-meta-plugin.md).
- Starter profile hardens file permissions via `file_meta` and adds `actions/55-cron.json` and `actions/60-grub.json`; the manifest is re-signed.

### Profiles

- Path, unit, owner, group and package fields are bounded to conservative character sets, and profiles are rejected at `verify` if they fall outside them. Characters with shell meaning (`$`, backtick, parentheses, quotes, backslash, glob, whitespace) are refused, as are `+` and `=` in paths; `@` is retained for systemd template unit paths. All shipped profiles are unaffected.

### Fixes

- Release archives can find the JSON schemas. Schema locations were derived from `runtime.Caller(0)`, a compile-time source path that no archive ships, so every subcommand failed with `open .../schema/profile.schema.json: no such file or directory`. The schemas are now embedded in the binary. This also removes a tampering surface: a user-editable schema on disk could previously be weakened to admit a profile the signer never validated.
- Firewall rollback restores `/etc/nftables.conf`. Apply appends an `include "/etc/nftables.d/*.nft"` line to it but journalled only the managed destination, so rollback reported completion while leaving that mutation behind. The file is now captured before apply and restored byte-for-byte, ordered so the managed file is reverted before the include that points at its directory.
- Rollback handles static and purged systemd units instead of failing on them.
- A service reload is re-run during rollback when the config dependency that triggered it was itself reverted.
- Plan next-step commands shell-quote the profile path, host, and overrides, and reuse the profile path as invoked rather than a normalised form.
- Profile verification success is logged in all modes, including debug.
- `ParseSemVer` accepts a prerelease suffix instead of failing on the patch component, and preserves it through `SemVer.String()`. Previously an embedded prerelease version aborted `version`, `plan`, and `apply` outright (#32).

### Plan and Reporting

- Plan output shows full diffs, package counts, and a clearer verify success line.

### Platforms and Packaging

- Release and CI build matrices add macOS (darwin) amd64 and arm64.
- Release archives ship a README describing the contents.

### Tooling

- `make check-schemas` fails when the committed schemas drift from the Go structs they are generated from, catching a hand-edited schema or a stale commit now that schema content is compiled in.
- `make check-standalone` builds hardline into a scratch directory, deletes the source tree and verifies the starter profile, guarding against the schema-path defect above. Both gates run in CI.
- Package coverage gating skips packages with no coverable statements instead of failing them at 0%.
- `make` no longer passes the dead `-X internals/cli.version` ldflag; the build banner version is read from `internals/cli/version.json`, the same source the binary embeds.

### Testing

- Integration suite rewritten around consolidated scenarios that verify OS state independently over SSH rather than trusting hardline's own output.
- Added reload-on-rollback and `file_meta` scenarios; scenarios now fail on swallowed remote assertions.
- Four integration scenarios cover the trust boundaries: root command injection, an action file outside the signed tree, an edited profile reaching apply, and the `/etc/nftables.conf` rollback. Each rejection case is paired with a benign twin built by the same generator, so a fixture broken for an unrelated reason cannot pass vacuously.
- New host-readiness wait and a one-shot `make itest-all` target.
- Unit coverage for each security fix was confirmed by mutation: reverting a fix turns its test red.

### CI

- Dropped the redundant release dispatch; the PAT-pushed tag already triggers `release.yml`.
- The build workflow skips release commits, since `release.yml` rebuilds the same tree.

### Documentation

- Documentation is published as a MkDocs site from `docs/` via GitHub Pages.
- Internals, profile and user docs corrected against the implementation: plugin contract, rollback ordering, remote execution, safety and trust, firewall and packages plugin fields, troubleshooting and install steps.
- Real run artifacts (plan, apply, rollback, verify, journal) published under [`docs/examples`](../docs/examples) and linked from the README.
- README retitled, distro support reframed, platform caveats moved into the docs.
- Corrected exit-code, report-write, version, and verify documentation.
