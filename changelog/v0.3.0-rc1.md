# v0.3.0-rc1 — 2026-11-04

First release candidate for 0.3.0, adding Rocky Linux support, dedicated SSH and audit plugins, and stricter verification and rollback. This release includes breaking profile, plugin API, and journal changes since [v0.2.0](v0.2.0.md).

### Breaking changes

- Package steps must name `packages_apt`, `packages_dnf4`, or `packages_dnf5`. The old `packages` plugin and package-manager config selector are gone. Profiles must declare an explicit OS family and numeric version; the engine compares them with the target's `/etc/os-release` instead of guessing a compatible distribution. Service unit names are used verbatim, so profiles must choose `ssh` or `sshd` for their target.
- Firewall steps must declare `main_config`: `/etc/nftables.conf` or `/etc/sysconfig/nftables.conf`. Each managed ruleset is included by its exact filename; a legacy directory-wide include is refused. Profiles sharing a main config must roll back in reverse apply order.
- Every plugin must implement `Validate(step, overrides)`. `InternalValidation` and the step-level `allow_unvalidated` escape hatch are removed. Plugin config schemas reject unknown fields, and verification checks unique step IDs and dependency order. Rebuild external plugins against this release's API, dependencies, and Go toolchain.
- Rollback accepts only version 3 journals with a valid checksum. Keep the binary that wrote an older journal when that run may still need to be reverted.
- Firewall rules and SSH account-access policy are applied as declared; the SSH plugin's authentication guard specifically refuses disabling public-key authentication.
- Repository profiles now live under `profiles/`. Published starter archives remain rooted at the profile directory itself.

### Added

- A signed Rocky Linux 9 starter profile alongside the Ubuntu 24.04 LTS starter, with a separate archive and checksum for each. Package backends cover apt, DNF 4, and DNF 5.
- An `ssh` plugin that stages an sshd drop-in, checks syntax before activation, reloads the declared service, and verifies effective settings with `sshd -T`, including optional connection contexts. Failed activation restores the previous file and, when needed, reloads the previous policy.
- An `audit` plugin that loads signed rules through `augenrules` and verifies the rule bodies reported by `auditctl`, with checks for policy states it cannot safely load.
- A host-wide mutation lock shared by apply and rollback, preventing concurrent runs from changing the same target.
- `rollback --local-journal` and a shell-quoted recovery command for a successful apply whose target journal could not be persisted. Extra positional CLI arguments are rejected instead of silently swallowing later flags.

### Security and correctness

- Verification consumes the exact signed bytes, requires manifest coverage for profile content, and validates every plugin's resolved configuration before remote execution. Validators receive independent copies of overrides.
- External plugin directories, their parent paths, and shared objects are checked for unsafe ownership, permissions, and symlinks. Local signing keys are opened without following symlinks and checked through the descriptor that is read; Unix local keys must be root-owned.
- Remote file snapshots distinguish a missing file from a failed stat, refused sudo, or lost connection. Framed probes tolerate login-shell output and GNU stat's quoted filenames, reject symlinks, and check the captured byte count against stat's size.
- Package probes fail closed, lock detection covers held unlinked locks, and purge and autoremove previews refuse undeclared collateral. RPM package queries resolve provides, transaction parsing uses a fixed locale, and plan and capture report the actual rollback fidelity.
- Firewall apply validates a staged candidate, loads the main config as one nftables transaction, and verifies the running rules in declared order. Rollback restores the main config and managed file before reloading the previous policy.
- Rollback resumes partially restored steps, pairs captured objects by identity, preserves file modes consistently, and restores indirect service enablement correctly. Runtime policy captures record changes without being dispatched as restorable objects.
- Both starter profiles explicitly enable the SSH service at boot and use the dedicated SSH and audit plugins.

### Documentation and tooling

- Versioned documentation builds from permanent release branches; `/dev/` tracks main. Prereleases remain available through GitHub Releases rather than being promoted to the stable documentation site.
- Updated authoring, execution, recovery, and installation documentation, plus regenerated example runs and a recorded demo.
- Integration fixtures are generated for each target, with Ubuntu and Rocky scenarios and a Fedora DNF 5 verification target.

### Known limitation

- The starter profiles still declare `min_hardline: "0.0.1"`, which understates their requirements. Use the profiles from this candidate with this candidate's binary. Updating and re-signing the profile minimums is tracked in the [release procedure](../docs/releasing.md#shipped-profile-minimums).
